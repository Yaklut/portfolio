Bank Muamalat (BMI) Sales Performance Dashboard

Four relational tables joined into one BigQuery master table and a Looker Studio sales dashboard, and five data-backed recommendations on products, inventory, cities and customers.

Context & question

Bank Muamalat, Indonesia's first Sharia bank (founded 1991), needed a data-driven way to evaluate sales performance across products, customer segments and cities. The data arrived as four related tables that had to be understood and combined before any analysis was possible.

Data provided

  • Customercontact details and city (2,123 customers)
  • Ordersdate, customer, product and quantity (3,339 orders)
  • Productname, category and price (70 products)
  • ProductCategorycategory names (7 categories)

02

Approach

  1. Identify primary keys

    CustomerID, OrderID, ProdNumber and CategoryID — one per table, each checked for uniqueness and missing values.

  2. Map the relationships

    One customer has many orders, one product appears in many orders, and one category holds many products. A check for orphan keys found none on any of the three links.

  3. Build the master table

    One BigQuery query joins the four tables and adds total_sales = quantity × price. The result has 3,339 rows — one per order — with no duplicated rows after the joins.

  4. Build the dashboard

    A two-page Looker Studio dashboard. Page 1: scorecards, sales and quantity by category, top 5 categories by sales and by quantity, sales by city, and a monthly trend. Page 2: category charts that drill down to products, and a top-10 product table.

  5. Recommend

    Turned the patterns into five recommendations, each tied to a figure and a dashboard view (see Recommendations below).

Data cleaning decisions

  • Decision

    Prices loaded as text

    The CSV uses a decimal comma (9,99). Read automatically, prices come out 100 times too large, so the products table is loaded as text and converted in SQL.

  • Decision

    Emails cleaned

    Raw emails look like abc@x.com#mailto:abc@x.com#. Only the part before the first # is kept.

  • Decision

    Category IDs cast to integers

    The category column arrives as text, so it is cast to an integer before joining to the category table.

The SQL

The queries behind the analysis, as written in the script. Only the project and dataset names are replaced with placeholders.

Validate keys and relationships

-- A. Primary key validation
-- Expected: total_rows = distinct_keys and null_keys = 0

SELECT 'customers' AS table_name, 'CustomerID' AS pk,
       COUNT(*) AS total_rows,
       COUNT(DISTINCT CustomerID) AS distinct_keys,
       COUNTIF(CustomerID IS NULL) AS null_keys
FROM `project_id.dataset.customers`
UNION ALL
SELECT 'products', 'ProdNumber',
       COUNT(*), COUNT(DISTINCT ProdNumber), COUNTIF(ProdNumber IS NULL)
FROM `project_id.dataset.products`
UNION ALL
SELECT 'orders', 'OrderID',
       COUNT(*), COUNT(DISTINCT OrderID), COUNTIF(OrderID IS NULL)
FROM `project_id.dataset.orders`
UNION ALL
SELECT 'product_category', 'CategoryID',
       COUNT(*), COUNT(DISTINCT CategoryID), COUNTIF(CategoryID IS NULL)
FROM `project_id.dataset.product_category`;

-- B. Relationship validation (orphan key check)
-- Expected: all counts = 0

SELECT
  (SELECT COUNT(*) FROM `project_id.dataset.orders` o
    LEFT JOIN `project_id.dataset.customers` c ON o.CustomerID = c.CustomerID
    WHERE c.CustomerID IS NULL) AS orders_without_customer,
  (SELECT COUNT(*) FROM `project_id.dataset.orders` o
    LEFT JOIN `project_id.dataset.products` p ON o.ProdNumber = p.ProdNumber
    WHERE p.ProdNumber IS NULL) AS orders_without_product,
  (SELECT COUNT(*) FROM `project_id.dataset.products` p
    LEFT JOIN `project_id.dataset.product_category` pc ON CAST(p.Category AS INT64) = pc.CategoryID
    WHERE pc.CategoryID IS NULL) AS products_without_category;

Sections A and B of SQLQuery.sql. The expected values are the ones the script checks against.

Build the master table

-- MASTER TABLE
-- Notes:
--  * CustomerEmail in the raw data looks like 'abc@x.com#mailto:abc@x.com#',
--    so it is cleaned with SPLIT(CustomerEmail, '#')[OFFSET(0)].
--  * products was loaded with all columns as STRING (decimal comma in the source
--    CSV), so Price is converted with CAST(REPLACE(Price, ',', '.') AS FLOAT64)
--    and Category with CAST(Category AS INT64).

CREATE OR REPLACE TABLE `project_id.dataset.master_table` AS
SELECT
  CAST(o.Date AS DATE)                        AS order_date,
  pc.CategoryName                             AS category_name,
  p.ProdName                                  AS product_name,
  CAST(REPLACE(p.Price, ',', '.') AS FLOAT64)  AS product_price,
  o.Quantity                                  AS order_qty,
  ROUND(o.Quantity * CAST(REPLACE(p.Price, ',', '.') AS FLOAT64), 2)  AS total_sales,
  SPLIT(c.CustomerEmail, '#')[OFFSET(0)]      AS cust_email,
  c.CustomerCity                              AS cust_city
FROM `project_id.dataset.orders` o
JOIN `project_id.dataset.products` p
  ON o.ProdNumber = p.ProdNumber
JOIN `project_id.dataset.product_category` pc
  ON CAST(p.Category AS INT64) = pc.CategoryID
JOIN `project_id.dataset.customers` c
  ON o.CustomerID = c.CustomerID
ORDER BY order_date, o.OrderID;

-- Validation (expected: 3,339 rows, total_sales ~ 1,754,750.57, total_qty 11,654)
SELECT COUNT(*)         AS row_count,
       SUM(total_sales) AS total_sales,
       SUM(order_qty)   AS total_qty,
       MIN(order_date)  AS start_date,
       MAX(order_date)  AS end_date
FROM `project_id.dataset.master_table`;

The master table query and its validation, from SQLQuery.sql.

Growth by category, 2020 vs 2021

-- E1. Sales and quantity growth by category, 2020 vs 2021
SELECT category_name,
       SUM(IF(EXTRACT(YEAR FROM order_date) = 2020, total_sales, 0)) AS sales_2020,
       SUM(IF(EXTRACT(YEAR FROM order_date) = 2021, total_sales, 0)) AS sales_2021,
       ROUND(SAFE_DIVIDE(SUM(IF(EXTRACT(YEAR FROM order_date) = 2021, total_sales, 0)),
                         SUM(IF(EXTRACT(YEAR FROM order_date) = 2020, total_sales, 0))) * 100 - 100, 1) AS growth_sales_pct,
       SUM(IF(EXTRACT(YEAR FROM order_date) = 2020, order_qty, 0)) AS qty_2020,
       SUM(IF(EXTRACT(YEAR FROM order_date) = 2021, order_qty, 0)) AS qty_2021
FROM `project_id.dataset.master_table`
GROUP BY category_name
ORDER BY sales_2020 DESC;

Query E1, one of the queries behind the recommendations.

    Repeat buying is already the norm

    Up to 7 orders from one customer

  • Geography

    Sales are spread thin across cities

05

Challenges & takeaways

  1. 01

    A decimal comma that inflated sales 100×

    Challenge

    When I loaded the product table into BigQuery, auto-detect read the price 9,99 as 999. The source files use a decimal comma, so every price, and every sales figure built on it, was 100 times too large.

    What I did

    Loaded prices as text and converted them in SQL with CAST(REPLACE(Price, ',', '.') AS FLOAT64). After that the master table matched: 3,339 orders, 11,654 units, and total sales of $1,754,750.57.

    Takeaway

    Never trust type auto-detection on files from another locale.

  2. 02

    A 7.8% drop, and 87% of it in one category

    Challenge

    Sales fell 7.8%, from $913,210 in 2020 to $841,540 in 2021. A headline like that invites a broad answer, such as promotions everywhere.

    What I did

    Splitting it by category showed otherwise: Robots alone account for about 87% of the decline ($402,835 to $340,670, down 15.4%), while Drones grew 3.3%. Robots are 42.4% of sales, so recovering them became the first of my five recommendations.

    Takeaway

    Break a headline number apart before deciding what to fix.

  3. 03

    Emails with extra text attached

    Challenge

    Raw emails look like abc@x.com#mailto:abc@x.com#.

    What I did

    Kept only the part before the first # using SPLIT.

    Takeaway

    Look at real values, not only column names, before trusting a field.

  4. 04

    Keys that had to match before joining

    Challenge

    The category column arrives as text but has to match an integer ID in the category table.

    What I did

    Cast it to an integer, checked every key for uniqueness and missing values, and ran an orphan-key check on all three links (none found).

    Takeaway

    Validate keys and relationships before building the master table.

07

Recommendations

  • Recommendation 1

    Recover Robots and position it as premium

    Robots bring in 42.4% of sales, yet fell 15.4% from 2020 to 2021 and account for about 87% of the total decline. Three products make up 54% of Robots sales: MICR-23K, RWW-75 and RLK-9920. Prioritise them with premium positioning and campaigns, and investigate why Robots dropped in 2021.

    Robots 402,835 → 340,670

  • Recommendation 2

    Forecast demand for Robots and Drones

    Robots sales swing about fivefold within a year, from 43,854 in June 2021 to 8,793 in October 2021. Monthly demand forecasting for the high-volume physical products helps avoid stock-outs at the peak and overstock in quiet months. eBooks, Training Videos and Blueprints are assumed to be digital and need no stock planning.

    Best month 95,402 · weakest 52,348

  • Recommendation 3

    Cross-sell from cheap to high-value products

    eBooks, Training Videos and Blueprints are 59% of units but 8.9% of sales, and 40.5% of customers bought only from these three. Build an upgrade path from Blueprints to Robot Kits and Drone Kits, then to Robots and Drones, with bundles such as a Drone Kit plus an eBook.

    Only 32.5% of customers ever bought Robots or Drones

  • Recommendation 4

    Retain declining cities, focus on the core

    Washington, the top city, fell 37% in 2021. Birmingham dropped about 95% and Sacramento about 69%. With 361 cities and the top ten at only 17% of sales, run retention programs in the declining cities and focus marketing on the core states (California, Texas and Florida) instead of spreading it across hundreds of small cities.

    Washington 33,988 → 21,394

  • Recommendation 5

    Activate passive customers, reward the best

    452 of 2,123 customers (21%) have never ordered. Of the 1,671 active ones, 59% have reordered and the top 10% generate 40% of sales. Send a first-purchase voucher to the passive group, add a VIP program for top customers, and push one-time buyers toward a second order.

    Top 10% of customers · 40% of sales

Limits: the data covers only two years and has no cost or margin, so every recommendation is based on sales and quantity, not profitability. The digital-product status of eBooks, Training Videos and Blueprints is an assumption based on the product type.

08

Data check & corrections

Every figure on this page was recomputed from the raw workbook in September 2026. Doing so turned up three issues in the original course submission. They are listed here rather than left out.

  • Found · Fixed in v2

    Orders versus units

    The dashboard's “Total Order” tile (11,654) sums the quantity column. There are 3,339 distinct orders; 11,654 is units sold.

  • Found · Fixed in v2

    No currency in the data

    The dataset has no currency field. The “Rp” prefix came from Looker's locale, and the customer addresses are American, so values are most likely dollars. The rebuilt dashboard shows dollars.

  • Found · Reworded

    “Stable” was too strong

    The original deck described revenue as stable. Monthly sales swing between 52.3k and 95.4k, and 2021 ended 7.8% below 2020.
