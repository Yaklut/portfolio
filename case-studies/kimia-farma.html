Kimia Farma Performance Analytics (2020–2023)

Four years of Kimia Farma sales, profitability and branch performance, turned from four raw datasets into a BigQuery analysis table and a Looker Studio dashboard.

Program
Project-Based Virtual Internship — Big Data Analytics · Kimia Farma × Rakamin Academy. Completed with an average score of 91.56 (Excellent).
Period
Apr 17–May 15, 2025
Data
4 CSV files · 672,458 transactions · 2020–2023
Tools
  • Google BigQuery
  • Google Looker Studio
  • SQL
01

Context & question

Kimia Farma, one of Indonesia's largest pharmaceutical companies, needed a data-driven way to evaluate business performance across its branch network. The brief covered 2020–2023 and asked for patterns in sales, profitability, promotion effectiveness and the service quality of its branches.

Data provided

  • Transactions — date, product, discount and transaction rating (672,458 rows)
  • Products — name, category and price (150 products)
  • Branch offices — location and branch rating (1,725 branches)
  • Inventory — stock counts per branch
02

Approach

  1. Import

    Loaded the four CSV files into Google BigQuery as native tables. Dates arrive as M/D/YYYY text, so they were loaded as strings and parsed in the next step.

  2. Model

    Wrote a SQL query with CTEs and LEFT JOINs that combines transactions, products and branches into one analysis table, adding nett_sales (price after discount) and nett_profit using the brief's gross-profit percentage by price tier (10% up to Rp50,000, rising to 30% above Rp500,000).

  3. Validate

    Wrote checks for row counts, unparsed dates, unmatched joins and totals, with expected values computed from the source CSVs.

  4. Visualize

    Built a two-page Looker Studio dashboard: filters, KPI tiles, a yearly nett sales vs nett profit view, a province profit map and top-10 provinces on page 1; branch, transaction, product-category, monthly-trend and stock views on page 2.

Design decisions

  • Decision

    Inventory is kept out of the join

    Its (branch, product) pairs repeat, so joining it to transactions would duplicate sales rows and inflate nett sales. It is summarised in a separate table and shown as its own chart.

  • Decision

    Branches are identified by ID and city

    branch_name has only three unique values, so it cannot tell branches apart.

  • Decision

    Province ISO codes added

    Each province is mapped to its ISO 3166-2 code so the geo map places every province correctly.

Build the analysis table

-- tabel_analisa: one row per transaction, joined to branch and product data
CREATE OR REPLACE TABLE `project_id.kimia_farma.tabel_analisa` AS
WITH base AS (
  SELECT
    t.transaction_id,
    PARSE_DATE('%m/%d/%Y', t.date) AS date,   -- CSV dates are M/D/YYYY strings
    t.branch_id,
    b.branch_category,
    b.branch_name,
    b.kota,
    b.provinsi,
    b.rating AS rating_cabang,
    t.customer_name,
    t.product_id,
    p.product_name,
    p.product_category,
    t.price AS actual_price,
    t.discount_percentage,
    -- gross margin tier by price (stored as a decimal: 0.10 = 10%)
    CASE
      WHEN t.price <= 50000  THEN 0.10
      WHEN t.price <= 100000 THEN 0.15
      WHEN t.price <= 300000 THEN 0.20
      WHEN t.price <= 500000 THEN 0.25
      ELSE 0.30
    END AS persentase_gross_laba,
    t.rating AS rating_transaksi
  FROM `project_id.kimia_farma.kf_final_transaction` AS t
  LEFT JOIN `project_id.kimia_farma.kf_kantor_cabang` AS b ON t.branch_id  = b.branch_id
  LEFT JOIN `project_id.kimia_farma.kf_product`       AS p ON t.product_id = p.product_id
)
SELECT
  transaction_id, date, branch_id, branch_name, kota, provinsi, rating_cabang,
  customer_name, product_id, product_name, actual_price, discount_percentage,
  persentase_gross_laba,
  -- nett sales = price after discount; profit is taken on the discounted price
  ROUND(actual_price * (1 - discount_percentage), 2)                         AS nett_sales,
  ROUND(actual_price * (1 - discount_percentage) * persentase_gross_laba, 2) AS nett_profit,
  rating_transaksi, branch_category, product_category,
  -- ISO 3166-2 code per province, so the Looker Studio geo map is accurate
  CASE provinsi
    WHEN 'Aceh' THEN 'ID-AC'
    -- ... one WHEN per province
    ELSE NULL
  END AS provinsi_iso
FROM base;

Core of 02_create_tabel_analisa.sql. The province mapping is shortened here.

Summarise inventory separately

-- Inventory is summarised on its own, never joined to transactions:
-- its (branch, product) pairs repeat, so a join would duplicate sales rows.
CREATE OR REPLACE TABLE `project_id.kimia_farma.tabel_stok_cabang` AS
SELECT
  i.branch_id, b.branch_name, b.kota, b.provinsi,
  COUNT(DISTINCT i.product_id) AS jumlah_produk,
  SUM(i.opname_stock)          AS total_stok
FROM `project_id.kimia_farma.kf_inventory` AS i
LEFT JOIN `project_id.kimia_farma.kf_kantor_cabang` AS b ON i.branch_id = b.branch_id
GROUP BY 1, 2, 3, 4;

The optional stock table, used for the stock-by-province chart on page 2.

Validation checks

-- A. Row count and unparsed dates.   Expected: 672,458 rows, 0 NULL dates
SELECT COUNT(*) AS total_baris,
       COUNTIF(date IS NULL) AS tanggal_null,
       COUNT(DISTINCT transaction_id) AS trx_unik,
       MIN(date) AS tgl_awal, MAX(date) AS tgl_akhir
FROM `project_id.kimia_farma.tabel_analisa`;

-- B. Branches or products that failed to join.   Expected: 0 and 0
SELECT COUNTIF(branch_name IS NULL) AS cabang_tak_cocok,
       COUNTIF(product_name IS NULL) AS produk_tak_cocok
FROM `project_id.kimia_farma.tabel_analisa`;

-- C. Grand totals.   Expected: nett sales ~ Rp321.17 billion, nett profit ~ Rp91.21 billion
SELECT SUM(nett_sales) AS total_nett_sales, SUM(nett_profit) AS total_nett_profit
FROM `project_id.kimia_farma.tabel_analisa`;

04

What the data shows

  • Trend

    Sales are flat, not growing

    Nett sales were Rp80.4, 80.0, 80.6 and 80.1 billion in 2020–2023, on roughly 168,000 transactions every year. A dip recurs each February.

    −0.5% · +0.7% · −0.6% year over year

  • Concentration

    One province carries the network

    Jawa Barat alone contributes 29.5% of nett sales and 198,723 transactions; the top three provinces contribute 43.6%.

    Top 10 provinces = 70.8% of nett sales

  • Product mix

    High-priced products drive the business

    Products priced above Rp500,000 are about half of all transactions but bring in 76% of nett sales and 80% of nett profit.

    > Rp500k: 52% of transactions · 76% of nett sales · 80% of nett profit

  • Service quality

    Branch rating does not predict transaction rating

    The 96 branches rated 5.0 average a transaction rating of 3.997, against 4.000 for all other branches. The five “lowest” 5-star branches are what picking the minimum of 96 branches produces by chance.

    Correlation between the two ratings ≈ 0.02

07

Data check & corrections

Every figure on this page was recomputed from the four raw CSV files in September 2026. Doing so turned up several issues in the original course submission. They are listed here rather than left out.

  • Found · Fixed

    Discount formula

    The original SQL divided discount_percentage by 100, but the raw values are fractions (0.00–0.15), so every discount was 100× too small. Nett sales and nett profit were overstated by 8.03% (Rp346.96 → Rp321.17 billion; Rp98.54 → Rp91.21 billion). The province ranking is unchanged.

  • Found · Relabeled

    Reading Looker's “M”

    In Indonesian-locale Looker, “M” abbreviates billions (miliar). “Rp346,96 M” on the dashboard means 346.96 billion, not million.

  • Found · Relabeled

    Customers are names, not IDs

    The dataset has no customer ID. The 264,601 figure counts distinct customer names, so it approximates unique customers.

  • Found · Reworded

    Rating gap is a selection effect

    The original dashboard highlighted five 5-star branches with the lowest transaction ratings and read it as a service-quality gap. Across all branches the two ratings are essentially unrelated, so the gap does not hold up.

  • Limit

    Fixed margins, not costs

    Nett profit applies the brief's gross-profit percentage for each price tier (10–30%), so profit patterns follow the price mix, not measured costs.
